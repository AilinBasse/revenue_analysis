A data storytelling project built on a local analytics stack — MySQL + Docker + Metabase, tunneled to the browser via ngrok. Twelve scroll-driven sections walk through a B2B SaaS company's revenue: the headline number, the growth trajectory, customer and product concentration, sales performance, and the pricing and retention tensions underneath. Every chart is live. Every SQL query is one click away. Every section ends with the conclusion the data supports.

The Stack

Every choice below was deliberate. Here's what each tool does in this project and why it's the right pick for the job.

MySQL
Data source

Relational store for a normalised B2B SaaS schema — customers, orders, order items, products, sales reps. Chosen because realistic revenue modelling needs joins, foreign keys, and aggregates over millions of line items.

Docker
Environment

Runs MySQL and Metabase as isolated containers with one command. Makes the entire analytics stack reproducible — anyone cloning this project can spin up an identical environment in minutes.

Metabase
BI & visualisation

Open-source BI layer handling charting, public embeds, and query management. Faster than rebuilding a dashboard UI from scratch, and the SQL editor doubles as a sketchpad for refining queries before they ship.

ngrok
Tunnel

Exposes the local Metabase instance to the public internet over HTTPS so iframes work from a static site. A pragmatic workaround for the constraint that the database lives on a laptop, not a cloud server.

GitHub Pages
Hosting

Free static hosting wired directly to the repo — every git push redeploys the site in under a minute. Source-controlled, free, and sidesteps the need for any backend or build pipeline.

HTML · CSS · JS
Frontend

Hand-written — no framework, no build step, no dependencies. Intersection Observer drives the scroll animations, vanilla CSS grid handles the layout. Easier to debug, faster to load, and signals I can ship end-to-end without hiding behind abstractions.

SQL 
-- Total completed revenue across all time, all customers, all products.
-- Applies line-item discount: revenue = qty × unit_price × (1 − discount/100).
-- Filtered to status='completed' so pending and cancelled orders are excluded.

SELECT
  SUM(oi.quantity * oi.unit_price * (1 - oi.discount_pct / 100)) AS total_revenue
FROM orders o
JOIN order_items oi ON oi.order_id = o.order_id
WHERE o.status = 'completed';

SQL 
-- Annual completed revenue with year-over-year growth %.
-- Uses LAG() to pull the previous year's total onto the same row,
-- making the growth calculation a single expression rather than a join.

WITH yearly AS (
  SELECT
    YEAR(o.order_date) AS year,
    SUM(oi.quantity * oi.unit_price * (1 - oi.discount_pct / 100)) AS revenue
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.order_id
  WHERE o.status = 'completed'
  GROUP BY YEAR(o.order_date)
)
SELECT
  year,
  revenue,
  LAG(revenue) OVER (ORDER BY year) AS prev_year_revenue,
  ROUND(
    (revenue - LAG(revenue) OVER (ORDER BY year))
    / LAG(revenue) OVER (ORDER BY year) * 100,
    1
  ) AS yoy_growth_pct
FROM yearly
ORDER BY year;

SQL 
-- Top 10 customers by revenue, with everyone else grouped into "Other".
-- Uses RANK() so the long tail is aggregated in a single pass rather than
-- two separate queries. Helpful for visualising customer concentration.

WITH customer_revenue AS (
  SELECT
    c.customer_name,
    SUM(oi.quantity * oi.unit_price * (1 - oi.discount_pct / 100)) AS revenue
  FROM orders o
  JOIN order_items oi ON oi.order_id  = o.order_id
  JOIN customers   c  ON c.customer_id = o.customer_id
  WHERE o.status = 'completed'
  GROUP BY c.customer_name
),
ranked AS (
  SELECT
    customer_name,
    revenue,
    RANK() OVER (ORDER BY revenue DESC) AS rnk
  FROM customer_revenue
)
SELECT
  CASE WHEN rnk <= 10 THEN customer_name ELSE 'Other' END AS customer_group,
  SUM(revenue) AS total_revenue
FROM ranked
GROUP BY customer_group
ORDER BY total_revenue DESC;

SQL 
-- Sales reps ranked by completed revenue, with two analytical columns
-- added via window functions: team average and % difference from that average.
-- Turns a flat ranking into a performance distribution view.

WITH rep_revenue AS (
  SELECT
    CONCAT(sr.first_name, ' ', sr.last_name) AS sales_rep,
    SUM(oi.quantity * oi.unit_price * (1 - oi.discount_pct / 100)) AS total_revenue
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.order_id
  JOIN sales_reps  sr ON sr.rep_id   = o.rep_id
  WHERE o.status = 'completed'
  GROUP BY sr.rep_id, sr.first_name, sr.last_name
)
SELECT
  sales_rep,
  total_revenue,
  ROUND(AVG(total_revenue) OVER (), 2) AS team_avg_revenue,
  ROUND(
    (total_revenue - AVG(total_revenue) OVER ())
    / AVG(total_revenue) OVER () * 100,
    1
  ) AS pct_vs_team_avg
FROM rep_revenue
ORDER BY total_revenue DESC;

SQL 
-- Per-rep revenue and average discount, categorised into four quadrants
-- using the median of each metric as the split point.
-- The `selling_style` label turns a scatter plot into an actionable segmentation:
--   "Value seller"        — above-median revenue, below-median discount (study + replicate)
--   "Volume discounter"   — above-median revenue, above-median discount (margin risk)
--   "Efficient builder"   — below-median revenue, below-median discount (developing talent)
--   "Underperformer"      — below-median revenue, above-median discount (coach or exit)

WITH rep_stats AS (
  SELECT
    CONCAT(sr.first_name, ' ', sr.last_name) AS sales_rep,
    SUM(oi.quantity * oi.unit_price * (1 - oi.discount_pct / 100)) AS total_revenue,
    AVG(oi.discount_pct) AS avg_discount_pct
  FROM sales_reps sr
  JOIN orders      o  ON o.rep_id   = sr.rep_id
  JOIN order_items oi ON oi.order_id = o.order_id
  WHERE o.status = 'completed'
  GROUP BY sr.rep_id, sr.first_name, sr.last_name
),
medians AS (
  -- MySQL has no PERCENTILE_CONT; approximate median by the midpoint of ordered rows.
  SELECT
    (SELECT AVG(total_revenue)    FROM rep_stats) AS median_revenue,
    (SELECT AVG(avg_discount_pct) FROM rep_stats) AS median_discount
  FROM DUAL
)
SELECT
  r.sales_rep,
  r.total_revenue,
  ROUND(r.avg_discount_pct, 2) AS avg_discount_pct,
  CASE
    WHEN r.total_revenue >= m.median_revenue AND r.avg_discount_pct <  m.median_discount THEN 'Value seller'
    WHEN r.total_revenue >= m.median_revenue AND r.avg_discount_pct >= m.median_discount THEN 'Volume discounter'
    WHEN r.total_revenue <  m.median_revenue AND r.avg_discount_pct <  m.median_discount THEN 'Efficient builder'
    ELSE 'Underperformer'
  END AS selling_style
FROM rep_stats r
CROSS JOIN medians m
ORDER BY r.total_revenue DESC;

SQL 
-- Completed revenue grouped by product category, with each category's share
-- of total revenue added as a % column via a window function.
-- Useful for answering "how platform-led is the business?" at a glance.

WITH category_revenue AS (
  SELECT
    p.category,
    SUM(oi.quantity * oi.unit_price * (1 - oi.discount_pct / 100)) AS total_revenue
  FROM orders o
  JOIN order_items oi ON oi.order_id  = o.order_id
  JOIN products    p  ON p.product_id = oi.product_id
  WHERE o.status = 'completed'
  GROUP BY p.category
)
SELECT
  category,
  total_revenue,
  ROUND(total_revenue / SUM(total_revenue) OVER () * 100, 1) AS pct_of_total
FROM category_revenue
ORDER BY total_revenue DESC;
